## Perubahan sesi lain yang diaudit

1. Transaksi offline yang membawa kode sesi lama/tidak dikenal tidak lagi
   otomatis ditempel ke sesi yang sedang aktif. Server mencari sesi kasir dan
   toko yang rentang waktunya mencakup waktu transaksi, termasuk sesi yang
   sudah ditutup. Jika tidak ditemukan, perilaku lama (sesi aktif) tetap menjadi
   fallback.
2. Pencarian sesi historis mengabaikan identitas kasir kosong dan berhenti aman
   bila nama maupun user ID tidak tersedia.
3. Jenis member dengan daftar metode pembayaran `NULL`/kosong diperlakukan
   sebagai konfigurasi yang belum diisi, bukan larangan semua metode. Transaksi
   tetap dapat berjalan memakai semua metode aktif.
4. API mengirim `izinTidakDisetel=true`; client menampilkan peringatan
   non-blocking agar admin dapat memperbaiki konfigurasi tanpa menghentikan
   kasir.
5. Daftar metode pembayaran sekarang dimuat ulang tepat sebelum dialog metode
   dibuka. Ini menutup perbedaan Kasir 1 dibanding Kasir 2/3 akibat snapshot
   konfigurasi lama tanpa mewajibkan logout/login. Permintaan selalu membawa
   member aktif sehingga pembatasan jenis member (termasuk Divisi) tetap
   dipatuhi.
6. Refresh metode tidak lagi menghapus pembayaran split yang masih sah. Split
   hanya dibatalkan bila metode di dalamnya sudah tidak diizinkan oleh respons
   server terbaru; picker dengan snapshot kosong tetap dapat diketuk untuk
   melakukan pemuatan ulang.
7. Rekaman `Rekaman 2026-08-24 190122.mp4` memperlihatkan hasil produk muncul
   dari cache lokal lalu hilang ketika respons server datang. Akar masalahnya
   adalah aksi `katalog` tidak selalu membawa lingkup toko untuk admin lintas
   toko, sehingga respons server kosong menimpa cache yang valid.
8. Lingkup aksi `katalog` sekarang dipusatkan di `ApiClient`: pilihan toko
   mengirim `toko_id`, sedangkan admin tanpa pilihan toko mengirim
   `semuaToko=true`. Lingkup eksplisit dari layar tetap tidak ditimpa.
9. Pencarian produk POS memakai nomor generasi permintaan. Respons cache atau
   server yang selesai terlambat tidak boleh lagi menimpa kata pencarian yang
   sedang aktif, termasuk pola mengetik-hapus-mengetik kata yang sama.
10. Pola respons asinkron yang sama diperbaiki pada Kasir Apotik, dialog produk
    Penjualan Sales, dan dialog produk SPJ. Kasir Apotik juga menghentikan
    indikator muat saat kata pencarian dikosongkan dan tidak menampilkan error
    dari permintaan yang sudah usang.

   semua metode; fallback semua metode hanya berlaku bila daftar izin benar-benar
   kosong/belum disetel.
